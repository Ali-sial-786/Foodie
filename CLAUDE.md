# CLAUDE.md: guidance for coding agents

## Layout
- `:shared`: KMP domain logic in `shared/src/commonMain/kotlin/app/nouri/core/`. No Android or `java.*` imports in commonMain. Tests in `commonTest` (JVM-only extras in `jvmTest`).
- `:app`: Android (Compose, Room, DataStore, CameraX, Keystore) in `app/src/main/kotlin/app/nouri/`. Manual DI in `AppContainer.kt`; screens in `ui/<feature>/` with a ViewModel next to each screen.
- Data: `data/usda-sr28/` (source), generated by `scripts/generate_food_data.py`. Never hand-edit `fooddb/generated/` or `assets/fooddb/`.
- Docs at the repo root. See README.md for the index.

## Commands
```bash
NOURI_SKIP_ANDROID=1 ./gradlew :shared:jvmTest   # works without the Android SDK
scripts/test.sh | scripts/lint.sh | scripts/benchmark.sh | scripts/fixtures.sh | scripts/debug-apk.sh
```
In the cloud sandbox Google Maven is blocked, so Android code is verified in GitHub Actions. Push to the working branch, then read the CI logs. Prefer `--offline` locally once dependencies are cached; Maven Central rate-limits.

## Conventions
- AI identifies; the engine calculates. Never let a model supply calories or nutrients.
- Every non-exact number carries provenance, a precision and (for estimates) a range. Confidence is shown as coarse labels, never percentages.
- Diary entries store frozen snapshots. Never recalculate history.
- Domain code takes dates and clocks as parameters. Use `util/SystemTime` only at platform edges.
- Room: bump the version and add a migration to `NouriDatabase.MIGRATIONS`. Never use a destructive fallback.
- Settings: add fields with defaults to `AppSettings`, which is stored as one JSON document.
- UI: never use colour alone (pair it with an icon or text), give interactive elements content descriptions, and label demo results as simulated.
- Match surrounding code style and keep KDoc for non-obvious rules.

## Hard constraints
- **Official Sign in with ChatGPT only.** No session-cookie extraction, browser automation, token scraping or subscription proxies.
- **Never incur API charges silently.** The API-key fallback requires explicit opt-in and is never used after `UsageLimitReached`. Never substitute demo results for a failed real request.
- Signing in is not consent to use plan usage. Check the granted scope.
- Photos go only to the provider the user selected, after consent, as processed copies (downscaled, metadata stripped).
- No analytics, no hard-coded secrets, no logging of tokens or keys. Secrets stay in the Keystore-encrypted store.
- Don't claim something works unless it has been run. Distinguish CI/simulated results from real-device results.
